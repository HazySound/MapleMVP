# 문의 대응
언제 읽나: 문의 게시판에 새 글이 올라와 원인을 찾을 때, 운영 D1을 조회·수정할 때, 로컬 화면으로 재현할 때

## 결정
- 문의 답변 문구는 '~습니다'체, 사용자가 직접 다듬는다. Claude는 내용만 제안
- 운영 D1 조회는 한 사람 행씩, 개인 자료는 `docs/private`·`frontend/test/private`에만(커밋 안 함)

## 주의
- wrangler는 저장소 루트에서 실행한다(frontend에서 하면 인증 오류가 났다)
- 관리자 계정은 member.admin=1로 찾는다
- 캡처를 받을 때 이미지 칸은 `hex(data)`로 받아 파일로 푼다. jpeg는 PIL로 png로 바꿔 시험한다
- 고치기 전 코드로 문의자가 본 문구가 그대로 나오는지(diag.scans의 msg) 먼저 재현한다

## 현재 방식
- 절차: post(본문·diag) · reply · image · vault(rows·pcroom·plan·eff) 받기 → `test/private/<이름>.test.ts`로 재현 → 고침 → 시험(공개·비공개) → 로컬 화면으로 확인 → 배포(사용자 지시 뒤) → 필요하면 보정값 주입(허락 뒤)
- 조회 예: `npx wrangler d1 execute maplemvp --remote --json --command "SELECT * FROM post WHERE id=N"`
- 화면으로 확인: 따로 띄운 Chrome 프로필(puppeteer-core, headless)에서 localStorage에 rows·pcroom·syncedAt·plan·eff를 넣고, 시계를 그 시각으로 돌려(evaluateOnNewDocument로 Date 바꿈) 파일을 올려 저장까지. 끝나면 프로필 폴더 삭제. 사용자 브라우저 저장소는 건드리지 않는다
- 운영자 본인 계정 저장값: `SELECT v.* FROM vault v JOIN member m ON m.uid=v.uid WHERE m.admin=1` → docs/private/me/vault-<날짜>.json (읽기만)
- wrangler 첫 호출이 Authentication error [code: 10000]로 실패해도 다시 하면 된 적 있다(2026-10-15)
- 비공개 시험은 약 12분. 헤드리스 화면 확인과 같이 돌리면 dorolong이 5초 제한에 걸린다 — 따로 다시 돌려 확인
- 5199 포트에 다른 세션의 vite가 떠 있을 수 있다(새로 띄우면 포트 겹침으로 꺼짐). 떠 있는 서버도 지금 파일을 내보내니 그대로 써도 된다(바닥 빌드 표시는 옛 해시)
- 공지 팝업이 로고·단추를 가릴 수 있어 확인 스크립트에서는 `.scrim`을 지운다
